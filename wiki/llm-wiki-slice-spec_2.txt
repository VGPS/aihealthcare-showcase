## Context and intent

Slice W1 established domain records (`WikiPageType`, `SourceRef`, `WikiPage`, `Contradiction`, `CompilationReport`) and port interfaces (`KnowledgeCompilationPort`, `WikiQueryPort`). This slice makes the pipeline runnable end-to-end so it can be triggered manually and stepped through in IntelliJ's debugger.

Design goals, in priority order:

1. **Debuggability first.** A manual REST endpoint (`POST /monitoring/wiki/compile`) must exist so the pipeline can be triggered from Postman/browser and breakpointed in IntelliJ.
2. **Provenance is persisted.** Every `SourceRef` is stored in a join table linking wiki claims to `NewsArticle` records.
3. **Revision audit trail.** Every wiki page update creates a revision record so history is never lost.
4. **Compilation reports are durable.** Each run's `CompilationReport` is persisted for dashboard display and audit.
5. **Raw sources remain immutable.** The wiki layer never mutates `NewsArticle` or any existing table.

## Architecture — End-to-End Flow

### STEP 1: TRIGGER

Three trigger paths, all converging on `KnowledgeCompilationPort.compileNewSources()`:

```
A. App startup    → FeedHarvestScheduler.harvestOnStartup()     [@PostConstruct]
B. Daily cron     → FeedHarvestScheduler.harvestDailyFeeds()    [04:00 UTC]
C. Manual REST    → POST /monitoring/wiki/compile               [new endpoint]
```

For paths A and B, add a `compileWikiPages(articles)` call in `FeedHarvestScheduler` after `routeForProcessing()` and `generateTopicSummaries()`:

```java
private void compileWikiPages(List<NewsArticle> articles) {
    log.debug("compileWikiPages() | articles={}", articles.size());
    try {
        CompilationReport report = knowledgeCompilationPort.compileNewSources(articles);
        log.info("compileWikiPages() | created={}, updated={}, contradictions={}",
                 report.pagesCreated().size(), report.pagesUpdated().size(),
                 report.contradictionsFlagged().size());
        // persist report via CompilationReportPort
    } catch (Exception e) {
        log.warn("compileWikiPages() | wiki compilation failed — harvest continues", e);
    }
    log.debug("compileWikiPages() | return=void");
}
```

For path C, create `WikiCompilationController` with `POST /monitoring/wiki/compile` that:
1. Fetches recent articles from `NewsArticleRepository` (last 7 days, configurable)
2. Calls `knowledgeCompilationPort.compileNewSources(articles)`
3. Returns the `CompilationReport` as JSON

### STEP 2: COMPILATION ADAPTER

`WikiCompilationAdapter implements KnowledgeCompilationPort` in `infrastructure.ai`:

```
compileNewSources(List<NewsArticle> newArticles):
```

## Increment 1 — JPA Entities and Repositories

### Entities (all in `infrastructure.persistence`)

**`WikiPageEntity`**
- Table: `wiki_pages`
- Fields: `slug` (PK, VARCHAR 255), `title` (VARCHAR 500), `pageType` (VARCHAR 50), `tags` (TEXT, comma-separated), `contentMarkdown` (CLOB/TEXT), `createdAt` (TIMESTAMP), `updatedAt` (TIMESTAMP nullable), `revision` (INT default 1)
- No `@GeneratedValue` — slug is the natural key

**`WikiSourceRefEntity`**
- Table: `wiki_source_refs`
- Fields: `id` (BIGINT auto-generated PK), `pageSlug` (VARCHAR 255, FK to wiki_pages), `articleId` (VARCHAR 255), `sourceName` (VARCHAR 255), `harvestedOn` (DATE), `excerpt` (TEXT nullable)

**`WikiRelatedSlugEntity`** (or embedded collection)
- Table: `wiki_related_slugs`
- Composite PK: `pageSlug` + `relatedSlug`

**`WikiContradictionEntity`**
- Table: `wiki_contradictions`
- Fields: `id` (BIGINT auto PK), `pageSlug` (VARCHAR 255), `priorClaim` (TEXT), `newClaim` (TEXT), `detectedAt` (TIMESTAMP)
- Prior/new source refs: stored as pipe-delimited articleIds (simple, matches existing patterns) or via join tables

**`WikiPageRevisionEntity`**
- Table: `wiki_page_revisions`
- Fields: `id` (BIGINT auto PK), `pageSlug` (VARCHAR 255), `revision` (INT), `contentMarkdown` (CLOB/TEXT), `compiledAt` (TIMESTAMP)

**`CompilationReportEntity`**
- Table: `compilation_reports`
- Fields: `id` (BIGINT auto PK), `runStartedAt` (TIMESTAMP), `runCompletedAt` (TIMESTAMP), `articlesProcessed` (INT), `pagesCreated` (TEXT, pipe-delimited), `pagesUpdated` (TEXT, pipe-delimited), `warnings` (TEXT, pipe-delimited)

### Repositories (all in `infrastructure.persistence`)

- `WikiPageRepository extends JpaRepository<WikiPageEntity, String>` — `findByPageType(String)`, `findAll()`
- `WikiSourceRefRepository extends JpaRepository<WikiSourceRefEntity, Long>` — `findByPageSlug(String)`
- `WikiContradictionRepository extends JpaRepository<WikiContradictionEntity, Long>` — `findByDetectedAtAfterOrderByDetectedAtDesc(Instant)`
- `WikiPageRevisionRepository extends JpaRepository<WikiPageRevisionEntity, Long>` — `findByPageSlugOrderByRevisionDesc(String)`
- `CompilationReportRepository extends JpaRepository<CompilationReportEntity, Long>`

## Increment 3 — Compilation Adapter (Spring AI / Claude)

### `WikiCompilationAdapter implements KnowledgeCompilationPort` (in `infrastructure.ai`)

Constructor-injected dependencies:
- `ChatClient chatClient`
- `WikiPageRepository wikiPageRepository`
- `WikiSourceRefRepository sourceRefRepository`
- `WikiContradictionRepository contradictionRepository`
- `WikiPageRevisionRepository revisionRepository`
- `String wikiCompilePrompt` (loaded from `prompts/wiki-compile.txt`)

```java
public CompilationReport compileNewSources(List<NewsArticle> newArticles) {
    Instant started = Instant.now();

    // 2a. Load existing pages
    List<WikiPageEntity> existingPages = wikiPageRepository.findAll();

    // 2b. Build prompt
    String prompt = buildPrompt(newArticles, existingPages);

    // 2c. Call Claude
    String response = chatClient.prompt().user(prompt).call().content();

    // 2d. Parse response
    List<WikiPage> pages = parsePages(response);
    List<Contradiction> contradictions = parseContradictions(response);
    List<String> warnings = parseWarnings(response);

    // 2e. Persist
    List<String> createdSlugs = new ArrayList<>();
    List<String> updatedSlugs = new ArrayList<>();
    for (WikiPage page : pages) {
        boolean exists = wikiPageRepository.existsById(page.slug());
        if (exists) {
            updatedSlugs.add(page.slug());
        } else {
            createdSlugs.add(page.slug());
        }
        persistPage(page);
    }
    for (Contradiction c : contradictions) {
        persistContradiction(c);
    }

    // 2f. Build report
    Instant completed = Instant.now();
    return new CompilationReport(started, completed, newArticles.size(),
            createdSlugs, updatedSlugs, contradictions, warnings);
}
```

### Prompt Template: `prompts/wiki-compile.txt`

```
You are a knowledge-base compiler for an AI-in-Healthcare intelligence service.

## Your task
Given {articleCount} newly harvested articles and {existingPageCount} existing wiki pages,
produce structured output that:
1. Creates new wiki pages for entities, concepts, or comparisons not yet covered
2. Updates existing pages with new information from the articles
3. Flags contradictions where new information conflicts with prior claims

## Input articles
{articleList}

## Existing wiki pages
{existingPageSummaries}

## Output format
Respond with structured sections using these exact headers:

### PAGE: {slug}
TITLE: {title}
TYPE: {ENTITY|CONCEPT|COMPARISON|OVERVIEW}
TAGS: {comma-separated tags}
STATUS: {CREATED|UPDATED}
SOURCES: {pipe-separated articleIds that support this page}
RELATED: {pipe-separated slugs of related pages}
CONTENT:
{markdown content}

### CONTRADICTION: {pageSlug}
PRIOR_CLAIM: {text of the prior claim}
NEW_CLAIM: {text of the new contradicting claim}
PRIOR_SOURCES: {pipe-separated articleIds}
NEW_SOURCES: {pipe-separated articleIds}

### WARNING: {message}
```

### Response Parser

A dedicated `WikiResponseParser` class (in `infrastructure.ai`) that:
- Splits the raw response by `### PAGE:`, `### CONTRADICTION:`, `### WARNING:` headers
- Parses each section into the corresponding domain record
- Handles malformed sections gracefully (log warning, skip)
- Uses traditional `for` loops — no streams

## Increment 4 — REST Trigger and Scheduler Wiring

### `WikiCompilationController` (in `web.controller`)

```java
@Slf4j
@Controller
public class WikiCompilationController {

    private final KnowledgeCompilationPort compilationPort;
    private final NewsArticleRepository articleRepository;

    // constructor injection

    @PostMapping("/monitoring/wiki/compile")
    @ResponseBody
    public CompilationReportResponse triggerCompilation() {
        // Fetch articles from last 7 days
        Instant since = Instant.now().minus(7, ChronoUnit.DAYS);
        List<NewsArticleEntity> entities = articleRepository.findByCreatedAtAfter(since);
        List<NewsArticle> articles = mapToDomain(entities);

        CompilationReport report = compilationPort.compileNewSources(articles);
        return CompilationReportResponse.from(report);
    }
}
```
