I've been building a full-stack AI-powered healthcare intelligence platform using Java 21, Spring Boot 3, and Spring AI 1.0 — and I wanted to share the architecture with this group.

The stack:

Java 21 records for every domain model — zero Lombok DTOs
Strict hexagonal (ports-and-adapters) architecture — the domain module has zero Spring imports
Spring AI ChatClient adapters for Claude, GPT, Perplexity, and Gemini — swappable via port interfaces
pgvector for RAG-powered semantic search and embedding dedup
Constructor injection only, spec-driven development from OpenAPI, Thymeleaf SSR
What it does:

Harvests AI healthcare news from 40+ RSS/API/web sources on scheduled crons
LLM-powered multi-model synthesis, sentiment analysis, and competitive framework scoring
Market digest pipeline: Perplexity research → Claude classification → Alpaca market data
Enterprise data export with async job execution, HMAC-signed downloads, and push delivery schedules
SAML2 SSO, Stripe billing, and a self-maintaining LLM wiki with contradiction tracking
Architecture highlights:

14 scheduled pipelines orchestrated through a single StartupPipelineOrchestrator with isolated try-catch per step
Every outbound dependency (AI, persistence, email, market data) is a port interface in the domain — adapters are pluggable
2,964 unit tests, no mocks of AI in CI — AI smoke tests isolated behind @Profile("ai-integration")
Single-module Maven build deployed to EC2 via systemd
The domain layer reads like plain Java — no annotations, no framework magic. Infrastructure adapters handle all the Spring AI wiring, JPA mapping, and HTTP client work. If you swap Claude for a local LLM tomorrow, you touch one adapter class.
